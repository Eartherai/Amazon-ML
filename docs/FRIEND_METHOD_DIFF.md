# Friend pipeline versus EXP-049 / EXP-045 (code audit, 2026-09-25)

The reported 0.96264695 (`HYB-CE-20K`) is **not E5 cosine plus LightGBM**. It is a jointly encoded E5 *cross-encoder* probability added to all 51 baseline features. The reported 0.96526623 (`TC-CE-BI-20K`) adds both that CE probability and BIENC-002 cosine to a rank-free 48-feature LightGBM, then assigns each target to the highest-scoring S1 among a full-corpus competitor search. EXP-049 uses a separately trained 3k-query E5 cross-encoder logit and the old 6k held candidate set; its scoped ownership comparison did not run the friend's competitor search. The 0.02 gap therefore cannot be attributed to assignment alone: friend same-model pair score is 0.95922542, target-centric improves it by 0.00604080. Friend's 0.9626 versus ours 0.9407 is primarily an unreplicated CE training/signal/candidate/evaluation combination, with different held populations.

## Immediate high-value sequence

1. Fix comparison basis: same 6k S1, same candidate pool, same exact `macro_f0_5` implementation, same truth; save per-pair score tables and per-S1 predictions. Reproduce friend's same-model pair rule before owner search.
2. Run full reverse lexical search (name/address top 10 S1 per target) and dense BIENC top 10 over **all** S1 in each country, for targets selected from full candidate pool at baseline score >= .02. Union with original candidates. The code does not compare all owners exhaustively; it searches all owners to retrieve top-K.
3. Generate rank-free 48 features for arbitrary competitor pairs using direct normalized char3 TF-IDF cosines; join saved CE probability and BIENC cosine. The friend implementation trains only on candidate rows of allowed folds, while scoring candidates plus competitor rows.
4. Sweep pair and exact best-owner decision on inner fold OOF predictions, apply outer-fold models, and compare independently with EXP-045. Save conflict counts, ownership accuracy and singleton/non-singleton slices.
5. To explain the CE gap, first ablate logit versus sigmoid, then lexical versus OOF-mined negatives at equal 3k, then expand owner-safe CE training toward 18k S1. This isolates training changes from target assignment.

## Caveats from code inspection

- The friend target search docstring's “all training S1” means the retrieval index contains all owners; `--competitors 10` means only top 10 dense owners per target are scored. Reverse lexical top 10 per route is additional where passed via `--competitors-from`.
- `target_centric.decide` filters competitor targets to those present in baseline OOF candidates. It does **not** create previously unretrieved S2/S3 targets as output candidates, but a competitor S1 may win a target even if that pair was absent from its forward candidates.
- The friend `pair_features` uses training owner metadata for labels and owner-safe masks; on test, equivalent feature construction must avoid label/owner information.
- Friend CE-002 holdout validation excludes held S1 queries from training, but `build_training_set` does not explicitly remove negatives whose target belongs to that CE holdout. This is a potential validation contamination for the internal CE holdout, not evidence that sample-B OOF was contaminated. Audit target overlap before using the CE holdout metric.
- No trained model artifacts or full scored pair files were present in the supplied friend repository snapshot, so reproducing the exact weights is impossible from code alone; method and reported metrics are auditable.
