# Reproducible multi-view feature foundation

All 24,229,173 source records converted to ZSTD level-3 Parquet. Every shard was read back and all four raw columns compared exactly to input, including blanks and Unicode. Total compressed bytes: 1806271306. No learned parameters or labels are used by preprocessing.

Materialized: original ID/name/address/country, explicit null/empty/blank flags, NFC/casefold/Unicode-LMN punctuation-spaced light text, Unicode decimal numeric-token lists. Optional compatible, accent-folded, compact, sorted, deduplicated, numeric-format and aggressive views are deterministically regenerated by the versioned `src.preprocessing` module. Learned maps remain disabled. Foundation transliteration recipe is pinned separately; Linux parity is not claimed.

The first materialization uses 750,000 rows/shard to preserve memory headroom while independent retrieval runs. Logical shard size is below the initially suggested 256–1024 MB range for some sources; this is a bounded initial choice, not an empirically proven optimum. Larger logical shard-size benchmarking remains pending. No millions-of-tiny-files design: only a few dozen shards, each tens of compressed MB. Row-group size is 100,000; no country partition assumptions.

Metadata includes input hashes/schema, transform/code hashes, source row counts, Python/Unicode/Polars versions and starting Git SHA. Code was uncommitted during execution, so module hashes identify the executed implementation; the eventual Phase3 code commit must accompany cloud runs.

CLI:

```sh
PYTHONPATH=code/business_entity_resolution POLARS_MAX_THREADS=2 .venv/bin/python -m src.data.materialize_views
```

Resuming verifies config/code identity and every completed shard hash. Changed data, config, source code or corrupted completed shards fail loudly and require a fresh version. Manifest: `artifacts/processed/prep-v001/manifest.json`. Raw S3 TSVs remain unchanged.

## Measured shard-size comparison

A subsequent local benchmark compared prefixes of the same 1.5M S1 records (warm filesystem cache, one repetition, ZSTD3, 100k row groups). All round trips were equal:

| Rows | Logical MiB | Stored MiB | Write s | Read s |
|---:|---:|---:|---:|---:|
| 375,000 | 65.93 | 25.29 | 0.35 | 0.096 |
| 750,000 | 131.85 | 50.56 | 0.77 | 0.228 |
| 1,500,000 | 263.76 | 101.13 | 1.39 | 0.409 |

The 1.5M alternative reaches the requested approximate 256MB logical target without a large size-efficiency change. Existing immutable 750k shards remain suitable for memory-bounded concurrent work; there is no evidence justifying another upload just to halve 35 objects. Larger 512–1024MB logical targets remain unbenchmarked. Evidence: artifacts/processed/shard-benchmark-v001/metrics.json. Peak whole benchmark process RSS 1.21 GiB.
